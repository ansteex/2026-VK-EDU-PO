
# Приложение для изучения технического английского в игровом формате
## ДЗ1
бизнес модель : B2C
### Elevator Pitch
Студентам технических специальностей часто сложно читать документацию на английском и разбираться в профессиональных терминах. При этом обычные приложения для изучения английского в основном учат повседневному общению, а технической лексике уделяют мало внимания.
Мое приложение - это что-то вроде Duolingo, только для изучения технического английского. В приложении можно будет изучать термины из программирования, инженерии и других технических направлений через короткие уроки, тесты и игровые задания.
Главная особенность в том, что пользователь сможет выбрать свою специальность и изучать именно тот английский, который нужен ему в учебе или работе.
В результате студентам будет проще читать документацию, понимать технические статьи и готовиться к собеседованиям на английском.

### Гипотеза по HADI
H (Гипотеза)

Студенты технических вузов и работающие технические специалисты заинтересованы в изучении профессионального английского через короткие интерактивные уроки и готовы платить за подписку 299 рублей в месяц.

A (Действие)

Создадим простой прототип с несколькими бесплатными уроками по техническому английскому.
Предложим 100 людям протестировать приложение: 50 студентам технических вузов и 50 работающим техническим специалистам.
После прохождения уроков предложим оформить подписку за 299 рублей в месяц.

D (Данные)

Измерим:
- количество пользователей, прошедших бесплатные уроки полностью;
- количество пользователей, оформивших подписку;
- конверсию из бесплатного использования в платную подписку;
- результаты студентов и работающих специалистов.

I (Выводы)

Если не менее 10% участников оформят платную подписку, гипотеза получит предварительное подтверждение.
Если менее 10% — пересмотрим стоимость подписки или функциональность приложения.

### Расчет CAC и LTV

Пользователи могут бесплатно проходить базовые уроки технического английского, а дополнительные материалы и функции доступны по подписке за 299 рублей в месяц.
Для расчёта юнит-экономики возьмем одного платящего пользователя.

Допустим, мы запустили рекламу в социальных сетях и получили следующие результаты:

| Показатель | Значение |
|---|---:|
| Рекламный бюджет | 10 000 руб. |
| Стоимость одного перехода | 20 руб. |
| Количество посетителей | 500 |
| Конверсия в регистрацию | 50% |
| Количество зарегистрированных пользователей | 250 |
| Конверсия из регистрации в покупку | 10% |
| Количество платящих пользователей | 25 |

Все значения являются предположениями для расчёта. Реальные показатели можно будет получить после запуска приложения.

### Расчет CAC

CAC = Расходы на привлечение / Количество платящих пользователей = 10 000 / 25 = 400 руб.

### Расчет LTV

Предположим, что пользователь будет оплачивать подписку в среднем 6 месяцев.

| Показатель | Значение |
|---|---:|
| Стоимость подписки | 299 руб/мес. |
| Средняя продолжительность подписки | 6 месяцев |
| Переменные расходы на пользователя | 49 руб/мес. |
| LTV по выручке | 1 794 руб |
| LTV | 1 500 руб |

В переменные расходы включим обслуживание пользователя, серверные ресурсы и комиссии за оплату.

LTV по выручке = 299 × 6 = 1 794 руб

LTV = (299 − 49) × 6 = 1 500 руб

Таким образом, один платящий пользователь принесёт примерно 1 500 рублей за всё время подписки без учёта расходов на его привлечение.

### Проверка сходимости экономики

LTV/CAC = 1 500 / 400 = 3,75.
При наших предположениях юнит-экономика сходится.

### Что будет, если пользователи начнут раньше отменять подписку?

Основной риск заключается в том, что пользователи могут перестать оплачивать подписку раньше предполагаемых 6 месяцев.
Посмотрим, как изменится экономика при разной продолжительности подписки.

| Продолжительность подписки | LTV | LTV/CAC |
|---|---:|---:|
| 3 месяца | 750 руб | 1,875 |
| 4 месяца | 1 000 руб | 2,5 |
| 5 месяцев | 1 250 руб | 3,125 |
| 6 месяцев | 1 500 руб | 3,75 |

При подписке на 3–4 месяца экономика уже не соответствует выбранному ориентиру.

Чтобы LTV/CAC был не меньше 3, при CAC = 400 руб пользователь должен оплачивать подписку в среднем не менее 5 месяцев.

### Функциональные и нефункциональные требования

### User Story 1

**Как студент, я хочу выбрать техническую специальность, чтобы изучать лексику, связанную с моей областью.**

Функциональные требования:

1. Пользователь может просматривать список доступных технических направлений.
2. Пользователь может выбрать одно направление из списка.
3. Пользователь после выбора направления видит в приложении уроки, соответствующие выбранной специальности.
4. Пользователь может изменить выбранное направление в настройках профиля.
5. Приложение сохраняет выбранное направление, чтобы пользователю не приходилось выбирать его при каждом входе.

Нефункциональные требования:

1. Список технических направлений должен загружаться не более чем за 3 секунды при стабильном интернет-соединении.
2. Интерфейс выбора специальности должен корректно отображаться на компьютерах и телефонах.
4. Интерфейс должен быть понятным и не требовать дополнительных инструкций.

### User Story 2

**Как студент, я хочу проходить короткие уроки, чтобы заниматься английским даже при нехватке свободного времени.**

Функциональные требования:

1. Пользователь может просматривать список доступных уроков по выбранному направлению.
2. Пользователь может открыть урок и приступить к выполнению заданий.
3. Каждый урок содержит задания на изучение и перевод технических терминов.
4. Пользователь может выбирать или вводить ответы на задания.
5. Приложение автоматически проверяет правильность ответов.
6. После завершения урока пользователь видит количество правильных ответов и полученные баллы.
7. Приложение сохраняет информацию о завершенных уроках.
8. Бесплатные уроки доступны всем зарегистрированным пользователям, а дополнительные - пользователям с активной подпиской.

Нефункциональные требования:

1. Один урок должен быть рассчитан примерно на 5–10 минут прохождения.
2. Урок должен загружаться не более чем за 3 секунды при стабильном интернет-соединении.
3. Проверка ответа должна занимать не более 1 секунды.
4. Интерфейс урока должен корректно отображаться на компьютерах и телефонах.
5. Прогресс прохождения уроков должен сохраняться в базе данных и быть доступным после повторного входа.
6. При временной потере интернет-соединения приложение должно сообщать пользователю об ошибке.

## ДЗ4

### DDD

#### 1. Управление пользователями

Назначение: регистрация, авторизация пользователей и управление их профилями.

Основные функции:
- регистрация пользователя;
- авторизация пользователя;
- хранение информации о пользователе;
- изменение данных профиля;
- сохранение выбранного направления обучения.

Глоссарий:
- пользователь - человек, зарегистрированный в приложении;
- аккаунт - учётная запись пользователя;
- профиль - информация о пользователе;
- авторизация - проверка прав пользователя на доступ к функциям приложения;
- направление обучения - техническая специальность, выбранная пользователем.

#### 2. Учебные материалы

Назначение: хранение и предоставление уроков и заданий по техническому английскому.

Основные функции:
- просмотр доступных технических направлений;
- просмотр списка уроков;
- отображение содержания урока;
- предоставление заданий на перевод терминов;
- разделение уроков на бесплатные и платные.
Глоссарий:
- направление обучения - область технического английского, например программирование или инженерия;
- урок - набор заданий по определённой теме;
- задание - упражнение для изучения или проверки знания терминов;
- термин - профессиональное слово или выражение на английском языке;
- каталог уроков - список доступных пользователю уроков.

#### 3. Прохождение обучения

Назначение: проверка ответов пользователя и сохранение результатов прохождения уроков.

Основные функции:
- начало прохождения урока;
- получение ответов пользователя;
- проверка правильности ответов;
- подсчёт правильных ответов;
- сохранение результатов;
- отображение прогресса обучения.

Глоссарий:
- прохождение урока - выполнение пользователем заданий одного урока;
- ответ - вариант, выбранный или введённый пользователем;
- правильный ответ - ответ, соответствующий заданию;
- результат урока - количество правильных ответов после завершения урока;
- прогресс обучения - информация о пройденных пользователем уроках.

#### 4. Игровые механики

Назначение: повышение мотивации пользователей с помощью игровых элементов.

Основные функции:
- начисление баллов за правильные ответы;
- отображение заработанных баллов;
- выдача наград за регулярное обучение;
- отслеживание серии ежедневных занятий.

Глоссарий:
- баллы - игровое вознаграждение за правильные ответы;
- награда - поощрение за достижения в обучении;
- серия занятий - количество дней подряд, в течение которых пользователь проходил уроки;
- достижение - выполненное пользователем условие для получения награды.

#### 5. Подписки и доступ

Назначение: управление платными подписками и доступом к дополнительным урокам.

Основные функции:
- отображение условий подписки;
- оформление платной подписки;
- проверка статуса подписки;
- предоставление доступа к платным урокам;
- ограничение доступа при отсутствии подписки.

Глоссарий:
- подписка - платный доступ к дополнительным урокам;
- тариф - условия предоставления подписки;
- платёж - операция оплаты подписки;
- статус подписки - состояние подписки пользователя;
- платный урок - урок, доступный только пользователям с активной подпиской.
## Критический путь MVP в формате BDD

**MVP - Прохождение урока технического английского**

### Сценарий 1. Успешное прохождение урока

**Дано:**

- пользователь авторизован в приложении;
- пользователь выбрал техническое направление «Программирование»;
- пользователь открыл бесплатный урок «Основные термины программирования»;
- урок содержит 5 заданий на перевод технических терминов;
- пользователь ещё не проходил выбранный урок.

**Когда:**

- пользователь нажимает кнопку «Начать урок»;
- пользователь последовательно выполняет все 5 заданий;
- пользователь нажимает кнопку «Завершить урок».

**Тогда:**

- система проверяет правильность ответов;
- система подсчитывает количество правильных ответов;
- система начисляет по 10 баллов за каждый правильный ответ;
- результат прохождения урока сохраняется;
- урок отмечается как пройденный;
- пользователь видит количество правильных ответов и заработанных баллов.

### Сценарий 2. Неуспешное открытие урока

**Дано:**

- пользователь авторизован в приложении;
- пользователь выбрал техническое направление «Программирование»;
- пользователь открыл каталог уроков;
- выбранный урок доступен только по платной подписке;
- у пользователя нет активной подписки.

**Когда:**

- пользователь выбирает платный урок;
- пользователь нажимает кнопку «Начать урок».

**Тогда:**

- система проверяет наличие активной подписки;
- система обнаруживает, что у пользователя нет активной подписки;
- доступ к заданиям урока не предоставляется;

## API-First

### API №1. Получение урока

**Назначение:** получение заданий выбранного урока.

**Запрос:**

```http
GET /api/lessons/1
```

**JSON при успешном получении урока:**

```json
{
  "lessonId": 1,
  "title": "Основные термины программирования",
  "tasks": [
    {
      "id": 1,
      "term": "compiler",
      "options": [
        "интерпретатор",
        "компилятор",
        "библиотека"
      ]
    },
    {
      "id": 2,
      "term": "variable",
      "options": [
        "функция",
        "массив",
        "переменная"
      ]
    }
  ]
}
```

**JSON при отсутствии подписки:**

```json
{
  "error": "Этот урок доступен только по подписке"
}
```

### API №2. Завершение урока

**Назначение:** отправка ответов пользователя для проверки и получения результата урока.

**Запрос:**

```http
POST /api/lessons/1/complete
```

**JSON тела запроса:**

```json
{
  "answers": [
    {
      "taskId": 1,
      "answer": "компилятор"
    },
    {
      "taskId": 2,
      "answer": "переменная"
    }
  ]
}
```

**JSON при успешном завершении урока:**

```json
{
  "lessonId": 1,
  "correctAnswers": 2,
  "totalTasks": 2,
  "points": 20,
  "status": "completed"
}
```

**JSON при ошибке:**

```json
{
  "error": "Необходимо ответить на все задания"
}
```
